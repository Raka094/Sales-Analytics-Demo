# Sales Analytics Demo

**Customer segmentation and pricing analysis for B2B sales data, with an AI-written summary for managers.**

![Python](https://img.shields.io/badge/Python-3.11+-1F5AA6)
![Streamlit](https://img.shields.io/badge/Streamlit-1.50+-0E9AA7)
![pandas](https://img.shields.io/badge/pandas-2.2+-0B2545)
![License](https://img.shields.io/badge/license-MIT-E8A33D)

A Streamlit tool that runs two classic consulting analyses in seconds:

1. **ABC segmentation**: which customers or products bring most of the revenue, and at what margin.
2. **Pricing opportunity**: which customers pay less than comparable peers for the same product, and what closing that gap is worth.

An **AI summary** then turns the results into a short note a manager can act on.

> **All data is synthetic.** It is generated by `generate_data.py` to look like the sales of a European chemical supplier. No real company data is used.

**Live demo:** https://sales-analytics-demo-ukmjasptxb8v99r6tz7ln6.streamlit.app/

## Key findings in the sample data

The app is built to tell one connected story, not to show separate features:

| Step | Finding |
| --- | --- |
| 1. Segmentation | **18% of customers** (class A) bring **80% of revenue** |
| 2. Margin | Class A has the **lowest gross margin**: 19.6%, compared with 25.8% in class C |
| 3. Cause | Volume discounts. Some large customers pay well below comparable peers |
| 4. Opportunity | Up to **€15.8M** (4.3% of revenue) if under-priced customers moved to the peer target |
| 5. Focus | **86%** of that opportunity sits with class A: a few negotiations, not hundreds |

## Features

**ABC segmentation**
- Segment by customers or by products
- Adjustable cut-offs (default 80% / 95% of revenue)
- Pareto curve with shaded class zones, and margin by class
- Full ranked list with CSV export

**Pricing opportunity**
- Peer groups by product and customer size
- Adjustable target percentile and minimum gap
- Opportunity by ABC class and by region
- Drill-down scatter plot per product, with target price lines
- Table of the largest individual gaps, with CSV export

**AI summary**
- Short manager summary written by an open-weight LLM via Groq's free API tier
- Only aggregated figures are sent to the model
- The exact facts are shown on screen, so every number can be checked
- Works without an API key, using a template summary

**General**
- Filters by region, industry and product family, applied to every tab
- Upload your own CSV, or use the sample data
- Column checks and clear error messages for wrong files



## Quick start

Requirements: Python 3.11 or newer.

```bash
git clone https://github.com/<your-username>/sales-analytics-demo.git
cd sales-analytics-demo

python -m venv venv
venv\Scripts\activate            # Windows
# source venv/bin/activate       # macOS / Linux

pip install -r requirements.txt
python generate_data.py          # creates sales_data.csv
streamlit run app.py
```

The app opens at `http://localhost:8501`.

### Enabling the AI summary (optional)

1. Create a free API key at [console.groq.com/keys](https://console.groq.com/keys). No payment card needed.
2. Copy `.streamlit/secrets.toml.example` to `.streamlit/secrets.toml`.
3. Add your key:
   ```toml
   GROQ_API_KEY = "gsk_..."
   ```
4. Restart the app.

The default model is `openai/gpt-oss-120b`. Free model lists change, so you can set `GROQ_MODEL` in the same file to use another one.

`secrets.toml` is listed in `.gitignore`. Never commit it.

## Using your own data

Upload a CSV with one row per order line and these columns:

| Column | Type | Example |
| --- | --- | --- |
| `month` | date | `2025-01-01` |
| `customer_id` | text | `C0001` |
| `region` | text | `DACH` |
| `industry` | text | `Automotive` |
| `product_id` | text | `P003` |
| `product_family` | text | `Polymers` |
| `volume_kg` | number | `374.6` |
| `net_price_eur_per_kg` | number | `8.28` |
| `revenue_eur` | number | `3100.70` |
| `cost_eur` | number | `2367.32` |

Rows with zero or negative volume, or negative revenue, are removed with a warning.

## Methodology

### ABC segmentation

1. Sum revenue per customer (or product) and sort from highest to lowest.
2. Calculate each one's share of total revenue, and the running cumulative share.
3. Assign classes using the share **before** each customer is added. The customer that crosses the 80% line therefore stays in class A.
4. Calculate margin per class from summed revenue and cost. Averaging customer percentages would give a small customer the same weight as a large one.

### Pricing opportunity

1. **Net price** per customer and product = revenue ÷ volume. This is volume-weighted, so one small order does not distort it.
2. **Peer group** = same product and similar yearly volume (Small, Medium or Large). Large buyers deserve lower prices, so comparing them with small buyers would be unfair.
3. **Target price** = a percentile of the peer group (default 75th). If a quarter of comparable customers already pay this much, it is achievable.
4. **Minimum gap** (default 5%). By definition, about 75% of any group sits below its own 75th percentile. Counting every small difference would overstate the result.
5. **Opportunity** = (target − actual price) × volume, for customers below the minimum gap.
6. Peer groups with fewer than 3 customers get no target.

## AI design

| Rule | Why |
| --- | --- |
| Python calculates every number; the LLM only writes text | Language models are unreliable at arithmetic |
| Only aggregated figures are sent, never customer rows | Confidential data stays in the tool |
| The prompt allows only the given facts | Reduces made-up numbers |
| The facts are shown next to the summary | Anyone can check the output |
| A cached result per set of facts | The same numbers never cost a second API call |
| Low temperature (0.2) | Consistent, factual wording |
| A template fallback without a key or on error | The app always works, even if the AI service is down |
| The provider is isolated in `ai_summary.py` | Switching to another LLM, such as a company-internal endpoint, changes one file |


## Deployment

The app runs for free on [Streamlit Community Cloud](https://share.streamlit.io):

1. Push the repository to GitHub, including `sales_data.csv`.
2. Sign in to Streamlit Community Cloud with GitHub.
3. Choose **New app**, then pick the repository and `app.py`.
4. Optional: under **Settings → Secrets**, add `GROQ_API_KEY`.

## Limitations

- **The opportunity is an upper bound, not a forecast.** Some customers will push back or reduce volume.
- **No contract data.** Some low prices are deliberate, for example strategic deals or fixed-term contracts.
- **Peer groups use product and volume only.** Region, contract length or service level could also justify price differences.
- **One year of data.** A single large order can move a customer into class A.
- **Custom CSS** relies on Streamlit's internal element names, which a future version may change.
